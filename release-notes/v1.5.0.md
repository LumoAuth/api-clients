## Highlights & New Features

### 1. Sign-in Links for Your Own Sign-in Form (`OAuth` API)

An application that renders its own sign-in form can now ask LumoAuth to mail a sign-in link.

- New operation `requestMagicLink`: `POST /orgs/{orgId}/api/v1/oauth/magic-link`. It needs no authentication.
- Request body: `RequestMagicLinkRequest`:
  - `email` (required): the address that gets the link.
  - `client_id` (required): the client ID of an active application of the organization.
  - `return_to` (optional): the page that the person goes to after signing in. It must be an absolute `https` URL (`http` only on localhost), and its origin must be one of the application's allowed origins or the origin of one of its redirect URIs. Without it, the person goes to the organization's default page.
  - `captcha_token` (optional): required when the organization protects sign-in link requests with a CAPTCHA.
- Response: `RequestMagicLinkResponse` with `status: "sent"`. The answer is the same whether or not the address belongs to an account, so the endpoint does not reveal which addresses have accounts.
- The call signs nobody in and mints no tokens. The person opens the link and confirms on the hosted page. LumoAuth then sends them to `return_to`, where your application starts its normal authorization flow.
- A browser request must come from one of the allowed origins of the application. Other origins get 403 `origin_not_allowed`.
- Errors: 400 `invalid_request`, `invalid_client`, `invalid_return_to`, `captcha_required` or `captcha_failed`; 404 `not_found` (unknown organization) or `magic_link_disabled`; 429 `rate_limited`.

```python
import lumoauth_api_client

configuration = lumoauth_api_client.Configuration()

with lumoauth_api_client.ApiClient(configuration) as api_client:
    oauth = lumoauth_api_client.OAuthApi(api_client)
    oauth.request_magic_link(
        "acme",
        lumoauth_api_client.RequestMagicLinkRequest(
            email="ada@example.com",
            client_id="my-spa",
            return_to="https://app.example.com/after-sign-in",
        ),
    )
    # Always {"status": "sent"}. Show "Check your email" to the person.
```

### 2. Agent Budgets in the Admin API (`Admin: Agents` API)

You can now set an agent's budget when you create or update the agent.

- New field `budgetPolicy` on `AdminAgentsCreateRequest` and `PutAdminAgentsUpdateRequest`. It is an object, so every client types it as a free-form map.
- Allowed keys:
  - Whole numbers: `max_api_calls_per_hour`, `max_api_calls_per_day`, `max_tokens_per_hour`, `max_tokens_per_day`, `max_steps` and `timeout_seconds`. The agent reads `max_steps` and `timeout_seconds` from UserInfo.
  - Amounts in USD: `max_cost_per_day_usd`, `max_cost_per_month_usd` and `hard_limit`.
  - Gateway-only amounts in USD: `max_cost_usd`, `monthly_usd` and `max_budget`.
- Each value must be greater than zero. The server refuses an unknown key or an invalid value with 400 on create, `PUT` and `PATCH`.
- On update, `budgetPolicy` replaces the whole policy. Send `{}` or `null` to remove the budget. A request without the field leaves the budget as it is.

When the budget is spent, the metered agent calls now document HTTP 429 `budget_exceeded`. The `Retry-After` header holds the seconds until the spent window starts again. These operations list the new 429 answer:

- `adminAgentsGenerateToken` (a token mint counts as one call)
- `ask`, `getRequestToken` and `getConnectionToken`
- `authorizeMcp`
- `issuePlatformToken` (`POST /aauth/agent/platform-token`), where the error is `access_denied`

```python
agents_admin = lumoauth_api_client.AdminAgentsApi(api_client)
agents_admin.admin_agents_create(
    "acme",
    lumoauth_api_client.AdminAgentsCreateRequest(
        name="invoice-bot",
        budget_policy={
            "max_api_calls_per_hour": 500,
            "max_tokens_per_day": 100000,
            "max_cost_per_month_usd": 50,
        },
    ),
)
```

### 3. API Key Lifetime on Rotation (`Admin: Agents` API)

`adminAgentsAgentsRotateKey` (`POST .../admin/agents/{agentId}/rotate-key`) and `adminAgentsRotateCredentials` (`POST .../admin/agents/{agentId}/rotate-credentials`) now take an optional request body.

- New model `AdminAgentsAgentsRotateKeyRequest`:
  - `apiKeyExpiresInDays`: days until the new key expires, from 1 to 3650. `null` means that the key never expires.
  - `apiKeyExpiresAt`: the exact expiry of the new key (ISO 8601, in the future). `null` means never. The server ignores it when `apiKeyExpiresInDays` is sent.
- Without either field, the new key keeps the current expiry date. If that date has already passed, the new key gets 180 days.
- `rotate-credentials` uses the lifetime only for an `api_key` agent. It ignores the body when it rotates a client secret.
- New field `api_key_expires_at` on `AdminAgentsAgentsRotateKeyResponse` (`null` means never).
- `rotate-key` now documents 400 for an agent that does not use an API key, or for an invalid lifetime.

### 4. Enterprise OpenID Connect Identity Links (`Admin: Users` API)

The identity link endpoints now support enterprise OpenID Connect connections next to SAML, LDAP and social providers.

- `AdminIdentitiesLinkRequest.type` accepts `oidc`. Send the connection ID in `idp_id` and the new `subject` field: the value of the connection's user identifier claim. A person can sign in through such a connection only after this link exists.
- `AdminIdentitiesListResponseDataBindingsItem.type` can be `oidc`, and the item has a new `subject` field. A link with `hashed: true` stores a long subject as a hash, so `subject` is `null`.
- The `type` path parameter of `adminIdentitiesUnlink` accepts `oidc`.

### 5. Sandbox API Key (`Admin: Sandbox` API)

`adminSandboxSpawn` now returns an API key for the new sandbox.

- `AdminSandboxSpawnResponse.data` is now `AdminSandboxSpawnResponseData`: all `SandboxTenant` fields plus a required `api_key`.
- The key holds every Admin API scope. It is shown only in this response and expires with the sandbox. Use it as `X-API-Key` on `/orgs/{sandbox slug}/api/v1/admin/...`.
- The sandbox has no user who can sign in. Add users with the key.
- The sandbox uses the plan of the organization that created it, and it cannot create sandboxes itself.
- New documented 403: the organization lacks the Developer sandboxes add-on (`feature_not_in_plan`), or it is itself a sandbox.

### 6. Webhook Delivery Changes (`Admin: Webhooks` API)

- **Replay:** `adminWebhooksDeliveryReplay` now queues a new delivery with the same event and payload. It does not change the original delivery. The response `data` is the new `AdminWebhooksDeliveryReplayResponseData` with `delivery_id` (the new delivery), `replay_of`, `webhook_id`, `event_name` and `status`. A disabled webhook sends nothing, so the call answers 409 until you enable the webhook.
- **Test:** `adminWebhooksTest` sends one `webhook.test` event with the same body, headers and signature as any other event. It records the event in the delivery history and does not retry a failed test. `AdminWebhooksTestResponse` has a new `deliveryId` field, which matches the `X-LumoAuth-Delivery` header.
- **Secret rotation:** for 24 hours after `adminWebhooksRotateSecret`, every delivery also carries `X-LumoAuth-Signature-Previous`, signed with the old secret. You can update your receiver without losing events. The `kid` of `X-LumoAuth-Signature` changes with every rotation.
- **Create and update:** the descriptions now list the accepted fields: `url`, `events`, `isActive` (also as `active` or `enabled`), `type` and `configuration`, plus `rotateSecret` on update. The server refuses a `secret` in the request, an unknown field and an event name that is not in the catalogue with 400. A new `url` for a webhook that has a signing secret needs `rotateSecret: true`, and the response then carries the new `secret` once.

### 7. Other New Fields

- `OAuthClient.cibaEnabled` (detailed responses only): whether the client may use CIBA (backchannel authentication).
- `AdminAuditLogsRetentionResponseData`: new `effectiveRetentionDays` (how long entries are kept now; `null` when nothing is deleted), `minRetentionDays` and `maxRetentionDays`. The descriptions of `retentionDays`, `autoDelete` and `planLimitDays` now explain how the organization's period and the plan's period work together.
- `AuthenticationSettings.password_policy`: new `require_lowercase`, `reject_breached_passwords`, `breached_password_min_count` (at least 1) and `check_breached_on_login`. A write is merged with the stored object.
- `ScimSettings.inbound.protected_attributes`: new `role_membership`. When it is `true`, SCIM cannot add or remove a member of a role through `/Groups`.

## Fixes & Specification Changes

### `approved_by.user_id` Is a UUID

`GetApprovalStatusResponseApprovedBy.user_id` (in the response of `getApprovalStatus`) was typed as an integer. The server has always returned the user's UUID there, so typed clients failed to parse the status of an approved request. The field is now a string in UUID format.

### Settings Fields That Had No Effect

These fields were stored or documented, but nothing read them. They are removed from the schema:

- `AuthenticationSettings.biometric_enabled` and `AuthenticationSettings.encrypt_client_secrets`. The server ignores them on write.
- `AuthenticationSettings.password_rotation_policy.notify_before_days` and `.history_count`.
- `ScimSettings.inbound.attribute_mapping` and `ScimSettings.outbound.attribute_mapping`.
- `ScimSettings.inbound.protected_attributes.roles` and `.permissions`. Use `role_membership` instead. `protected_attributes` now lists only `email`, `name`, `active` and `role_membership`, and the server does not store other keys.

### Value Rules in `AuthenticationSettings` and `ScimSettings`

- `no_mfa_action` is now an enum: `allow`, `prompt`, `email` or `block`.
- `session_timeout` is the idle timeout in seconds, from 300 to 1,209,600 (14 days).
- `password_policy.min_length` is from 8 to 128.
- `password_rotation_policy.max_age_days` is from 1 to 730.
- `social_login_enabled` is described as a legacy flag. Social sign-in on the hosted sign-in page follows the enabled social providers, not this flag.
- `ScimSettings.outbound.verify_tls` is always `true`. The server rejects `false` with 400.
- `ScimSettings.outbound.tls_certificate`: send `null` or an empty string to remove it. A change requires you to enter the stored secrets again.

### Documented Responses

The specification now lists answers that the server already gives:

- 403 `plan_limit_reached`: on `ask` when the month's included Ask API calls are used, and on `token` when the month's included machine-to-machine tokens or active agents are used. This applies only to plans without overage.
- 403 `insufficient_scope` for a scope-narrowed agent token: on `reportAgentUsage`, `createApproval` and `getConnectionToken`.
- 403 `task_suspended` on `requestPermission`, when continuous access evaluation suspends the task on this request.
- 403 on `evaluateTask` for a caller who is not a user of the organization with the `jit.approve` permission.
- 403 `sso_required` with a `redirect_url` on `submitLoginJson`, for an administrator of an organization that requires single sign-on for administrators.
- 429 `rate_limited` on `getAgentCard`.
- 400 on `abacPoliciesCreate` for a `priority` outside 0 to 1000.
- 400 on `adminMcpServersCreate` for an invalid `resource_uri`, or for a field that cannot be set (`include_scope_in_challenge`, `bearer_methods_supported`).
- 400 on `adminAgentsGenerateToken` for an agent that only takes DPoP-bound tokens.

### Other Description Changes

- `listPermissions` now returns permissions that are granted to the user directly, next to permissions from roles. Such a permission has `source: "direct"`.
- `updateClient` (`PUT /admin/clients/{clientId}`) works like `PATCH`: only the fields that you send change.
- `createClient`: a public client (`isConfidential: false`) has no secret, so `OAuthClientSecretIssued.secret` is absent.
- `adminMcpServersCreate` documents `scope_descriptions`. A server that is not OAuth-protected (`auth_mode: "none"` or `transport: "stdio"`) is stored with the three `require_*` switches off.
- `AuditLogEntry.status` is the result of the event: `success`, `failure`, `pending` or `partial`.

## Breaking Changes

The operation set is unchanged apart from the new `requestMagicLink`. No operation or model was removed. These changes can break code that compiles against 1.4.0:

| Change | Effect in typed clients |
| :--- | :--- |
| `GetApprovalStatusResponseApprovedBy.user_id`: integer → UUID string | TypeScript `string`, Python `str`, Go `string`, Java `UUID`, C# `Guid`, PHP `string` |
| `AdminSandboxSpawnResponse.data`: `SandboxTenant` → `AdminSandboxSpawnResponseData` | Code that declares the type of `data` as `SandboxTenant` must use the new type. It has the same fields plus `api_key`. |
| `AdminWebhooksDeliveryReplayResponse.data`: `WebhookDelivery` → `AdminWebhooksDeliveryReplayResponseData` | The response no longer holds the full delivery. Read `delivery_id` and `replay_of` instead. |
| `AuthenticationSettings.no_mfa_action`: string → enum | TypeScript `AuthenticationSettingsNoMfaAction`, Java and C# `AuthenticationSettings.NoMfaActionEnum`, Swift `AuthenticationSettings.NoMfaAction`. Python validates the value. Go and PHP keep a string. |
| Removed fields (see [Settings Fields That Had No Effect](#settings-fields-that-had-no-effect)) | Their getters, setters and properties are gone. |

Notes per language:

- **Java:** `adminAgentsAgentsRotateKey` and `adminAgentsRotateCredentials` (and their `WithHttpInfo` and `Async` variants) have a new third parameter. Pass `null` to keep the 1.4.0 behaviour.
- **C#:** the new optional rotation parameter keeps source compatibility, but you must recompile. Some constructors changed:
  - `AdminIdentitiesLinkRequest` has a new `subject` parameter before `nameId`. A positional call such as `new AdminIdentitiesLinkRequest(TypeEnum.Saml, idpId, "name-id")` still compiles, but it now sets `subject` instead of `nameId`. Pass `nameId:` as a named argument.
  - `AuthenticationSettings` no longer has `biometricEnabled` or `encryptClientSecrets`, and `noMfaAction` is `NoMfaActionEnum?`.
  - `AdminWebhooksTestResponse` has `deliveryId` before `message`, and `AdminIdentitiesListResponseDataBindingsItem` has `subject` before `legacy`. This matters if you build these responses in tests.
- **Go:** the module path stays `github.com/lumoauth/api-clients/go`, so `go get` picks up the type changes above in a minor version. Check your build before you upgrade. `ScimSettingsInboundProtectedAttributes` no longer has `AdditionalProperties`.
- **TypeScript:** the class API takes one request object and is unchanged. If you call the functional API (`AdminAgentsApiFp` or `AdminAgentsApiFactory`) with positional arguments, the third argument of `adminAgentsAgentsRotateKey` and `adminAgentsRotateCredentials` is now the request body. Move `options` to the fourth position. `ScimSettingsInboundProtectedAttributes` no longer has an index signature.
- **Python and PHP:** the new rotation parameter is optional, so existing calls work unchanged.
- **Rust (not published):** `admin_agents_agents_rotate_key` and `admin_agents_rotate_credentials` take a new `Option<AdminAgentsAgentsRotateKeyRequest>` argument. Struct literals of changed models must add the new fields or end with `..`.
- **Swift and Ruby (not published):** the rotation parameter is optional. The removed fields are gone from the models.
- Every Java model file shows a change, because the generator stamps the generation time in `@javax.annotation.Generated`. Only the models listed above changed in content.
