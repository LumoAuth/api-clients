## Highlights & New Features

### 1. Agent Usage Reporting (`Agents` API)

LumoAuth does not see an agent's model calls. An agent can now report the tokens and cost of its model calls, so that the token and cost limits of its budget count real usage.

- New operation `reportAgentUsage`: `POST /orgs/{orgId}/api/v1/agents/me/usage`.
- Request body: `AdminAgentsReportUsageRequest` with `tokens` (integer, 0 to 100,000,000) and `cost_usd` (number, 0 to 100,000). The agent endpoint shares this request type with the Admin endpoint below, so the type name starts with `Admin` in every client.
- Response: `ReportAgentUsageResponse` with two fields:
  - `recorded`: the tokens and cost that the server added (`AdminAgentsReportUsageResponseDataRecorded`).
  - `budget`: the agent's budget after the report, in the same shape as `budget_policy` in UserInfo. `exhausted: true` means that the next metered call (Ask API call, token request or JIT request) gets HTTP 429.
- A report is not a metered call. The server accepts it even when the budget is spent.
- Only agent credentials can report usage. The server answers other tokens and portal test tokens with 403 (`test_token_not_accepted` or `cross_tenant`).
- The server limits how often each agent can report (429 `rate_limited`). If your agent calls models often, send fewer, larger reports.

```python
import lumoauth_api_client

configuration = lumoauth_api_client.Configuration(access_token=agent_access_token)

with lumoauth_api_client.ApiClient(configuration) as api_client:
    agents = lumoauth_api_client.AgentsApi(api_client)
    result = agents.report_agent_usage(
        "acme",
        lumoauth_api_client.AdminAgentsReportUsageRequest(tokens=1530, cost_usd=0.0042),
    )
    if result.budget and result.budget.get("exhausted"):
        ...  # The next Ask, token or JIT request gets 429.
```

### 2. Admin Usage Reporting (`Admin: Agents` API)

A trusted component of your organization can report usage for an agent. Examples are an AI gateway's spend callback or an orchestrator that sees the agent's model calls.

- New operation `adminAgentsReportUsage`: `POST /orgs/{orgId}/api/v1/admin/agents/{agentId}/usage`.
- Request body: `AdminAgentsReportUsageRequest`, the same type as above.
- Response: `AdminAgentsReportUsageResponse`. Its `data` field (`AdminAgentsReportUsageResponseData`) has `recorded` and `budget`, the same fields as the agent endpoint returns.
- The report adds the tokens and cost to the same budget windows as the agent's own report. It is not a metered call, and the server accepts it even when the budget is spent.
- Errors: 400 for a missing, negative, too large or non-numeric value, 401 without authentication, 403 without admin privileges, 404 for an unknown organization or agent.

### 3. `budget_policy` in `UserinfoResponse` (`OIDC` API)

- Added the `budget_policy` field (object, agents only) to `UserinfoResponse`. It holds three things:
  - The budget limits that are set: `max_api_calls_per_hour`, `max_api_calls_per_day`, `max_tokens_per_hour`, `max_tokens_per_day`, `max_cost_per_day_usd`, `max_cost_per_month_usd` and `hard_limit`. Limits without a value are left out.
  - The usage in the current UTC windows: `api_calls_this_hour`, `api_calls_today`, `tokens_used_this_hour`, `tokens_used_today`, `cost_today_usd` and `cost_this_month_usd`.
  - `exhausted`: `true` when a limit is reached and the next metered call would get 429.
- The `userinfo` response description now says that an agent token needs no `openid` scope, because an agent reads only its own record.

## Fixes & Specification Changes

### `security` Alternatives in `openapi.json`

In the 1.3.0 `openapi.json`, eight operations listed `[]` as their "no authentication" security alternative. A security requirement must be an object, so the correct value is `{}`. 1.4.0 fixes these operations:

- `POST /oauth/token`, `POST /oauth/revoke`, `POST /oauth/introspect`, `POST /oauth/par`, `POST /oauth/device_authorization`, `POST /oauth/bc-authorize`
- `GET` and `POST /mcp/{serverId}/challenge`

The generated clients did not change. The fix matters if you generate your own clients or run other tools on `openapi.json`.

### "Any JSON Value" Fields

- `AbacAttributeDefinition.defaultValue`, `AbacResourceAttribute.value` and `SetUserAttributeResponseData.value` are now the schema `{}` (any JSON value) instead of `{ "nullable": true }`.
- In the TypeScript client, their type changed from `any | null` to `any`. Both types accept the same values, including `null`. The other clients did not change.

### SCIM Secret Fields

- The write-only secret fields of `ScimSettings` now describe `null` as a second `oneOf` alternative next to `RedactedSecret`, instead of a top-level `nullable`. The generated clients did not change.

## Upgrade Notes

- Every 1.3.0 operation and model is still present, and the operation signatures are unchanged.
- **C#:** the `UserinfoResponse` constructor has a new optional `budgetPolicy` parameter before `clientId`. Code that passes `clientId` as a positional argument no longer compiles. Pass it as a named argument (`clientId: ...`) instead.
- **Rust (not published):** `UserinfoResponse` has a new public field, so a struct literal must add `budget_policy` or end with `..`.
- Every Java model file shows a change, because the generator stamps the generation time in `@javax.annotation.Generated`. Only the models listed above changed in content.
